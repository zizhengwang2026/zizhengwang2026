## 🚀 Featured Builds

### 🦾 SO-101 × ACT — Real-Hardware Imitation Learning

*My first end-to-end embodied AI pipeline. Not a simulation. Not a tutorial. Real hardware, real data, real policy.*

<div style="background: linear-gradient(135deg, #fef3c7, #fde68a); padding: 18px; border-radius: 12px; border-left: 5px solid #f59e0b; margin: 12px 0;">

**🎯 Mission:** Build a robotic arm that sees an object and grasps it autonomously — using imitation learning, no hand-coded control.

**⭐ Why it matters:** This is the canonical **"perceive → decide → act"** embodied-AI loop, run on physical hardware.

</div>

#### 🧰 Hardware Stack

| Component | Role | Specs |
|---|---|---|
| **D-Robotics S600** | Edge AI compute | RDK board, aarch64 |
| **SO-101 Arms** × 2 | Leader + follower | 6-DOF, FEETECH servos |
| **Cameras** × 2 | Visual input | Dual-view workspace |
| **Host PC** | Teleoperation + training | Linux + Python |

#### 💻 Software Stack

| Layer | Tool |
|---|---|
| OS (board) | Debian (aarch64) |
| Env | Miniconda + HuggingFace **LeRobot** |
| Algorithm | **ACT** — Action Chunking Transformer |
| Compute | PyTorch |
| Calibration | FEETECH servo SDK |

#### 🔁 The 8-Step Pipeline (Run Hands-On)

```bash
# Step 1: Flash the S600 board
xburn → SSH in

# Step 2: Build a clean aarch64 environment
miniconda → pip install lerobot

# Step 3: Calibrate leader and follower arms
python -m lerobot.calibrate --id FEETECH --center --limits

# Step 4: Collect demonstration data
python -m lerobot.teleop --dual-camera --record

# Step 5: Audit collected episodes
python -m lerobot.replay --episode 1

# Step 6: Train ACT
python -m lerobot.train --algo ACT --epochs 50

# Step 7: Inspect loss curve
python -m lerobot.check --loss-curve

# Step 8: Deploy
python -m lerobot.policy_server &
python -m lerobot.act_client
```

#### 🐛 Bugs I hunted down (one by one)

| Problem | Why it happens | How I fixed it |
|---|---|---|
| SSH drops during flash | power glitch on USB-C | powered hub + retry loop |
| Conda installs x86 wheels on aarch64 | default channel wrong | pinned `aarch64` channel explicitly |
| `externally-managed-environment` (PEP 668) | Debian 12 hardening | `--break-system-packages` or venv |
| Servo jitter during teleop | noise on TTL bus | added capacitor + shorter cable |
| ACT loss plateau | too few epochs, bad LR | 50 epochs, swept 1e-4 / 5e-4 / 1e-3 |

#### 📊 Result

> ✅ **The arm completes vision-based grasps autonomously** — my first end-to-end embodied loop on physical hardware.

🔗 Code, weights, and notes → [`embodied-dea-journey/so101-act`](https://github.com/zizhengwang2026/embodied-dea-journey)
